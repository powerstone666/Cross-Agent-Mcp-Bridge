## Facts
- 2026-10-24: Relay sends now queue in arrival order. Relay-handled command and file approvals are accepted automatically unless `send_to_agent` has `requireHumanApproval: true` or terminal chat uses `/review `. MCP prefers CLI connectors for Codex, Claude, and Gemini to make this possible; Copilot and IDE fallbacks can still have provider-owned prompts. `RELAY_COORDINATOR_AGENT` selects the room coordinator, defaulting to the first available agent; new rooms persist this name and onboarding/member listings show workers' coordinator.
- Codex binary ships inside the VS Code extension: ~/.vscode/extensions/openai.chatgpt-*/bin/<platform>/codex. `codex app-server` speaks JSON-RPC over stdio, one JSON message per line, no "jsonrpc" field.
- Protocol schema can be regenerated: `codex app-server generate-json-schema --out <dir>` (write it outside the repo).
- Flow: `initialize` -> notify `initialized` -> `thread/start` -> `turn/start` ({threadId, input:[{type:"text",text,text_elements:[]}]}). Replies stream as `item/agentMessage/delta`, the turn ends with `turn/completed` (status completed | interrupted | failed).
- Approvals arrive as server requests `item/commandExecution/requestApproval` and `item/fileChange/requestApproval`; the answer is `{decision: "accept" | "acceptForSession" | "decline" | "cancel"}`. `codex exec` cannot ask for approvals, so the adapter uses app-server.
- Codex approval and sandbox restrictions were removed on 2026-10-23. The relay still forwards approval requests when Codex sends them.
- AHP host side (VS Code -> relay) is not built yet; Phase 0 in plan.md is still open.

- Two Codex modes (`RELAY_CODEX_MODE`): `cli` (default; own app-server + own thread) and `ide` (wrapper in front of the extension's app-server; turn runs in the IDE's thread). The relay now handles CLI approvals automatically by default. IDE mode is unit-tested against a fake server and was checked live through the VS Code wrapper.
- The Codex extension starts its own `codex app-server` over stdio (no shared socket), so the only way into the IDE's thread is to sit in front of it via `chatgpt.cliExecutable`. cross-agent_mcp marks that setting DEVELOPMENT ONLY.
- Codex CLI approval policy and sandbox are sent only if the user sets `RELAY_CODEX_APPROVAL_POLICY` / `RELAY_CODEX_SANDBOX`; otherwise Codex applies the user's own defaults. In automatic mode, IDE fallback requests `approvalPolicy: never` for new threads, but existing IDE threads retain their own settings. New IDE threads open in the IDE's workspace folder unless `RELAY_TARGET_REPO` is set. Sockets live in `~/.crossagentbridge/ide-sockets/<agent>/`. ~/.codex/config.toml pre-approves one Google Drive tool (`approval_mode = "approve"`); the relay cannot override per-tool approvals.
- Not done yet: log redaction, per-turn timeout, transcript .md view, `.gitignore` entry for `.crossagentbridge/`, AHP host (Phase 0 in plan.md).
- Agent rooms: terminal chat and `npm run init -- --apply` initialize `.agent-room/config.yaml` and `.agent-room/rooms/<room>/`; starting the MCP HTTP server does not create a room. MCP clients call `get_room_setup`, then explicitly call `create_room` and `join_room` as needed. The suggested room defaults to `backend` and can be changed with `RELAY_AGENT_ROOM`. The relay session ID is written into `ROOM.md` and participant files; events are mirrored into room logs only after a room exists.

- Layout: `src/main.ts` is the one entry (`npm start` = terminal chat, `npm run mcp` = `main.ts mcp`). Folders are named by role: `bridge/` (generic core), `ai-connectors/<agent>-connector/` (everything about one agent), `mcp-layer/`, `terminal-layer/`, `vscode-setup/`. Agents are `AgentModule`s listed only in `src/agent-modules.ts`. Generic code must not contain agent-specific behavior. MCP tool instructions live in `skills/tools.md`; room workflows live in `skills/rooms.md`; shared server and client configuration instructions live in the root `setup.skill.md`.
- Safety facts: IDE adapters refuse a socket folder that is not private; terminal approval text is stripped of control codes; the wrapper's Unix socket messages are shape-validated in `codex-ide-protocol.ts`; relay-only replies are matched by request id so a `turn/interrupt` reply is never mistaken for a `turn/start` reply; an interrupt sent before the turn id is known is remembered and sent later; turn events are matched by turn id so a human's own turn on the same thread cannot leak in.
- Connectors: codex (cli+ide, tried live), claude (cli: `claude -p` stream-json with `--permission-prompt-tool stdio`; ide: wrapper via `claudeCode.claudeProcessWrapper`), copilot (ide only, VS Code agent host protocol over a Unix socket with `ws`; the relay never confirms tool calls, VS Code does), gemini (cli: ACP over stdio, approval mode follows Gemini's default or `RELAY_GEMINI_APPROVAL_MODE`; ide: Antigravity's local hub, gRPC-Web JSON at /exa.language_server_pb.LanguageServerService/<Method> with header x-codeium-csrf-token, found from `ps` args `agy --hub --hub-port= --csrf_token= --add-dir=`; one cascade per folder: the model comes from GetUserStatus (userStatus.cascadeModelConfigData.defaultOverrideModelConfig.modelOrAlias.model; GetCascadeModelConfigs returns nothing and an invented model name fails with `unknown model key`), then StartCascade, SendUserCascadeMessage, poll GetAllCascadeTrajectories, read GetCascadeTrajectorySteps; the relay never calls HandleCascadeUserInteraction; the hub's home page embeds the token, so never save it; `RELAY_GEMINI_MODE=cli|ide`, ide is used automatically over MCP). Claude/Copilot/Gemini are tested with fakes only. The `agy` command line is not used (unknown approval behavior). Sockets: `~/.crossagentbridge/ide-sockets/<agent>/`; env vars are `RELAY_<AGENT>_...`.
- Root cause of the "empty workspace" report: the wrapper reused a relay-made thread (cwd = an empty test folder) as "the IDE's thread". Fixed: relay threads are never the IDE thread and are reused only for the same folder.
- Still open: log redaction, per-turn timeout, `.gitignore` entry for `.crossagentbridge/`, AHP layer, real-world checks of Claude/Copilot/Gemini, extracting the code the IDE connectors share (socket listing, wrapper server, allowlists), confirming the IDE lists relay-started threads.
- VS Code launches Codex as `codex -c ... app-server ...` (options before `app-server`), so wrapper detection uses `isAppServerInvocation`, not argv[0]. "Reload Window" does not restart a running wrapper; quit/reopen VS Code or kill the wrapper process.
- Wrapper starts its own thread when the IDE has none (`newThreadParams` on the socket `send` message); the new thread is saved as a `codex_vscode` session.
- `skills/` contains only tool and room usage guidance (`tools.md`, `rooms.md`, and their `GUIDE.md` index). Server, VS Code adapter, and client setup are consolidated in the root `setup.skill.md`.
